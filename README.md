# TalesUntold: лаунчер и обновления клиента

Полный клиент игроки один раз скачивают с Google Drive. Дальше `TalesUntoldLauncher.exe` в корне клиента при каждом запуске берёт `manifest.json` из последнего релиза этого репозитория и докачивает только файлы, которые отличаются от присланного клиента. Сделано на основе лаунчера L2Pure (`sant0shiq-l2classic/tools/client-update`), только вместо своего сервера на порту 8080 используются GitHub Releases.

## Что в репозитории

- `launcher/Launcher.cs` → `launcher/build.bat` собирает `TalesUntoldLauncher.exe` встроенным в Windows `csc.exe` (.NET Framework 4, ставить ничего не нужно). Настройки в `launcher/launcher.ini` рядом с exe.
- `publish_github.py` выпускает обновление клиента новым релизом (нужен Python 3 и залогиненный `gh`).
- `news.json` хранит новости и патчноуты для вкладок лаунчера. Лаунчер читает его из ветки `main`, так что новость можно поменять прямо на GitHub, без релиза.
- `tests/test_github_flow.py` проверяет весь путь целиком: публикацию, редиректы как у GitHub, докачку, сохранение `Option.ini` и отказ от подменённого файла.

## Как устроены релизы

- Каждый изменённый файл загружается ассетом с именем, равным его SHA256. В `manifest.json` для каждого файла указаны путь, размер, SHA256 и ссылка на ассет.
- Если файл не менялся с прошлого релиза, он не загружается снова: манифест ссылается на ассет в старом релизе. **Поэтому старые релизы удалять нельзя.**
- `gh` сначала загружает всё в черновик и только потом публикует релиз, так что игроки никогда не увидят релиз, загруженный наполовину.
- Ассет может весить не больше 2 ГБ, скрипт это проверяет.

## Лаунчер

- Включён TLS 1.2: без этого .NET 4 не может подключиться к GitHub.
- Сверка файлов быстрая, потому что хеши кешируются в `launcher-cache.json`. «Проверить файлы» пересчитывает все хеши заново.
- Каждый файл скачивается во временный, затем проверяются размер и SHA256 (3 попытки). Пути с `..` и пути вне папки клиента отклоняются.
- `Option.ini`, `User.ini`, `WindowsInfo.ini`, логи и скриншоты игрока никогда не публикуются и не перезаписываются.
- Самообновление: если в релизе новый `TalesUntoldLauncher.exe`, он заменяет себя сам.
- Если обновления недоступны, можно играть на текущей версии. `TalesUntoldLauncher.exe --update` делает то же без окна.
- Фон: `launcher-bg.jpg` рядом с exe (1100×620). Без него рисуется тёмный градиент.

## Как выпустить обновление

1. Один раз, на том самом клиенте, который залит на Google Drive:
   `python publish_github.py base C:\Users\User\Desktop\TalesUntold\client base.json`
   Файл `base.json` сохраните: он описывает клиент, который есть у игроков.
2. Измените файлы клиента (patch DAT, interface, L2.ini и т.п.) в рабочей копии.
3. `python publish_github.py publish <клиент> --base base.json --version 2026-11-10 --dry-run` покажет, что уйдёт в релиз.
4. Та же команда без `--dry-run` создаст релиз `client-2026-11-10`. Игроки получат его при следующем запуске лаунчера.

Если когда-нибудь перезальёте полный клиент на Google Drive, пересоздайте `base.json` из нового клиента.

## Риски

Файлы клиента принадлежат NCSoft. Поэтому в публичном репозитории лежат только изменённые файлы, а не весь клиент. Если на репозиторий придёт жалоба DMCA, основной приватный репозиторий с сервером не пострадает.
